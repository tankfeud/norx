Why Norx

A serious engine. A joyful language. Zero compromises.

Norx wraps all of ORX — rendering, physics, audio, animation, FX — and layers the parts Nim does best right on top.

Data-driven by design

Spawn a sprite, a rigid body, a sound scene or an entire HUD from one line and an INI section. Tweak values, watch the game update — no recompile.

Complete, current bindings

Every ORX 1.17 function, generated with Futhark and guarded by source annotations, so the wrapper can never silently drift from upstream headers.

Idiomatic Nim layer

Value-based vector math with +, * and friends, object property overloads, plain Nim strings and booleans — ORX idioms, Nim feel.

Type-safe interop

orxBOOL is a distinct ABI-sized type that converts to bool transparently, and every return value can be checked with .isSuccess / .isFailure.

Cross-platform

Windows, Linux, macOS and Android, driven by ORX's plugin architecture. Your Nim code stays identical; only the build flags change.

Open & hackable

zlib-licensed, no strings attached. Norx grew out of the Tankfeud game project and is developed in the open on GitHub.

Norx 0.8.1

The API-polish release: everything that once felt like "C with Nim syntax" now feels like Nim.

Release notes → Changelog →
  • Value-oriented vector math: newVector(x, y) plus real operators — no more pointer juggling for everyday work
  • Object properties as values: getPosition(), setScale(...), getSpeed() and friends take and return orxVECTOR
  • Plain Nim strings for input names, config sections, text, FX and sounds
  • Distinct, ABI-safe orxBOOL with automatic boolean conversion
  • Explicit status predicates: .isSuccess and .isFailure
  • Two complete game samples: Pong and Boulder Dash
Heads up: orxBOOL is no longer an integer alias. Code that treated it as a number needs an explicit conversion — boolean use is unchanged.
Get started

From zero to bouncing objects in minutes

All you need is Nim 2.2.4 or newer — ORX 1.17 comes along as a pinned Git submodule.

01 /

Clone & prepare ORX

Fetch the wrapper and initialize the pinned ORX 1.17 submodule:

git clone https://github.com/tankfeud/norx.git
cd norx
git submodule update --init
# build ORX locally per README —
# no system install needed
02 /

Install

Grab Norx from the Nimble registry:

nimble install norx

# requires Nim ≥ 2.2.4
03 /

Run the samples

Start tiny, then play the full games — samples run from their own directory:

cd samples/ball
nim c ball.nim
./ball            # hold → to move

cd ../pong
nimble build && ./pong
